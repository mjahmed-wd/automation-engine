22. DOM injection via evaluate evaluate

The evaluate action runs your expression in the page's main JS world via CDP Runtime.evaluate — same realm as the page's own inline <script> tags. Anything you can do in DevTools Console, you can do here: append elements, inject stylesheets, delete nodes, rewrite text, call the page's globals (Redux store, jQuery, framework hooks). The page can't tell whether the mutation came from its own scripts or from outside. This is the escape hatch for "make a one-off change while the automation runs" — for example dimming rows you've already processed in a CRM list, hiding noisy UI, or surfacing a custom progress badge.

Multi-statement code needs an IIFE because Runtime.evaluate runs in script mode and doesn't return the last expression — write (() => { …; return value; })(). Return values get JSON-serialized, so primitives and plain objects survive into ctx.outputs via saveAs; DOM nodes come back as {}. Mutations persist until the next navigation or reload.

23. Retry policy retries + retryDelay

Phase 5 Batch 2: every locator-using step accepts retries and retryDelay. Non-fatal failures and one specific kind of fatal failure (covered, an overlay-blocked click) trigger a retry; disabled / read-only / no-match / not-a-select do NOT retry because those states won't fix themselves. Two widgets below: a "becomes-clickable-after-1200ms" button that's hidden on load, and a "covered-clears-after-1500ms" overlay that auto-dismisses. Open each section's example, refresh the page (so the timer resets), then Run — the engine retries until the underlying condition is satisfied.

not clicked

not clicked

{
  "name": "Retry: becomes-clickable-after-1200ms (succeeds with retries: 3)",
  "tag": "action",
  "steps": [
    { "action": "evaluate", "expression": "window.__resetRetryDemo()" },
    {
      "action": "click",
      "xpath": "//button[@id='late-btn']",
      "timeoutMs": 500,
      "retries": 3,
      "retryDelay": 500
    },
    { "action": "get", "xpath": "//p[@id='result-late']", "property": "textContent", "saveAs": "out" }
  ]
}

Expected: step 1 invokes __resetRetryDemo() which hides the button and starts a fresh 1.2s timer. Step 2's first click attempt fails (button still hidden), waits 500ms, retries, fails again, retries — by attempt 3 or 4 the setTimeout has fired and the button is visible. Side panel log: Attempt 1/4 failed: ... Retrying in 500ms… repeats until Step click succeeded on retry 2/3 (or similar). Output out = "clicked". Re-runnable without a page reload — the reset call rebuilds the timer each time.
